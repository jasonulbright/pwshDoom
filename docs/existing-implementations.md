# Existing implementations

Initial survey: 2026-09-10. Refreshed 2026-09-28 from the listed repositories' current READMEs and source trees. This is a comparison of documented architecture and scope, not an equivalent benchmark or independent campaign certification. It is not an exhaustive proof that no other port exists.

| Offering | Engine and display | Evidence and limits |
| --- | --- | --- |
| [oleyska/ManagedDoomPowershell](https://github.com/oleyska/ManagedDoomPowershell) | Managed Doom translated into PowerShell; software rendering through Silk.NET/GLFW/OpenGL, with separate graphics/audio libraries. | The maintainer says most features work, documents a wipe-effect transition bug and poor Windows performance, and recommends PowerShell 7.5.4/7.6. It is an important PowerShell engine ancestor, not a terminal renderer. Current README and its listed dependencies were rechecked on 2026-09-28; see [`ORIGIN.md`](../src/ManagedDoom/ORIGIN.md) for the exact adopted revision and local modifications. |
| [nick0451/doom-powershell](https://github.com/nick0451/doom-powershell) | Single PowerShell script with WAD/BSP rendering, sector geometry and an ANSI/character display. | The current README describes textures, sprites, collision, monsters, doors, weapons and exits. It also explicitly lists lifts, moving floors, walk-over triggers, and sound as unfinished. It is a useful pure-PowerShell terminal comparison; its author-described support and performance are not independently reproduced here. |
| [spidychoipro/terminal-doom-pwsh](https://github.com/spidychoipro/terminal-doom-pwsh) | Native `doomgeneric` engine and C Windows Terminal backend; PowerShell scripts build and launch the executable. | The README says it converts the original 320x200 framebuffer to ANSI truecolor half-block cells and accepts a user-supplied WAD. It runs from PowerShell on Windows Terminal, but gameplay, rendering and audio are not implemented in PowerShell. |
| [cryptocode/terminal-doom](https://github.com/cryptocode/terminal-doom) | Native `doomgeneric` engine with a Zig application loop and `libvaxis` terminal frontend using the Kitty graphics protocol. | The README describes sound effects plus a small set of music tracks and support for additional user files. It reports testing on macOS/Linux; Windows may compile but the README says a compatible local terminal is not available. This is a substantial compiled-engine alternative, not a Windows Terminal or PowerShell-algorithm competitor. README reviewed 2026-09-28; not built or benchmarked in this study. |
| [dcouple/terminal-doom](https://github.com/dcouple/terminal-doom) | Chocolate Doom compiled to WebAssembly, presented through a local browser and the Kitty graphics protocol. | The README targets Kitty-protocol terminals on macOS/Linux, ships the shareware episode, offers sound effects but disables music, and says saves are session-local. Full IWAD use is described as a user replacement. This is a browser/WASM terminal experience, not Windows Terminal or PowerShell gameplay. README reviewed 2026-09-28; not built or benchmarked here. |
| [resumex/doom-over-dns](https://github.com/resumex/doom-over-dns) | PowerShell transports WAD/assemblies via DNS; compiled C# Managed Doom runs in a graphical window. | README and source tree identify the compiled engine and omitted audio. Not a PowerShell translation or terminal renderer. |
| [ray0911/Doom-Powershell](https://github.com/ray0911/Doom-Powershell) | Small PowerShell/Windows Forms grid raycaster. | Inspected `Test.ps1`: generated maze, drawn gun, basic movement. No WAD-based Doom engine. |
| [PrismRewind/PowerDoom](https://github.com/PrismRewind/PowerDoom) | Repository describing a Build-engine recreation. | Inspected tree contained only a README and license; no playable implementation in that tree. |

Other compiled terminal presentations include [jserv/kitty-doom](https://github.com/jserv/kitty-doom), which documents a C engine and Kitty graphics protocol, and browser/WASM projects such as `dcouple/terminal-doom` above. These show that “Doom in a terminal” has several real implementations; they are prior art for display experiments, not evidence about PowerShell engine performance.

## Assessment

This project occupies a narrower intersection: Doom gameplay, rasterization, terminal encoding and audio synthesis/mixing algorithms written in PowerShell, with a Windows Terminal host and user-supplied game data. Existing options show different tradeoffs: the graphics-window PowerShell port supplies an engine foundation; the compact PowerShell raycaster is terminal-native but documents missing Doom actions and sound; and the more direct terminal ports use compiled engines or terminal protocols not supported by Windows Terminal. That makes pwshDoom a distinctive fit for the language-and-host constraint, not a demonstrated performance or compatibility winner. We have not run equivalent campaign, fidelity, audio or pacing trials against these alternatives. The survey must not be used to claim “best,” “first,” or full-WAD support. Check licenses before adopting code.

**Measured follow-up:** the first batch evaluated nick0451's BSP walls/flats/sky renderer from commit `6b0072973cd08fb83edc521e834e4070cda4b0a5`, using a separately stored source file and the user's Steam Doom IWAD. The low-resolution combined renderer/encoder/write loop reached 75–76 completed writes/second with the study's ANSI encoder in the corrected UTF-8 runs. This excludes gameplay and displayed-frame verification. See [full findings](findings-2026-09-10.md); it is not a reproduced upstream full-game performance claim.

## Assets

Users supply commercial IWADs. The engine source release does not release commercial graphics, music, or maps. [Freedoom explains the separation](https://freedoom.github.io/about.html) and provides independent replacement content. [Chocolate Doom documents obtaining the shareware IWAD](https://www.chocolate-doom.org/wiki/index.php/FAQ#Why_does_the_game_crash_just_after_the_title_screen_appears?). Availability of a WAD does not prove a particular port supports its full feature set.
